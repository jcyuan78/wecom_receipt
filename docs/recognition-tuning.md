# 提高发票识别率：模板、少样本与微调

> 结论先说：**不建议一上来就训练模型**。先用“整图识别 + 日期先验 + 少样本/模板”，通常能解决 80% 的问题；只有同版式发票量大、且少样本仍不稳定时，才值得做 LoRA 微调。

---

## 1. 先判断问题属于哪一类

| 现象 | 更可能的原因 | 优先手段 |
|---|---|---|
| 日期/金额偶尔读错 | 图片质量、字体、手写 | 提高拍摄质量、换更大模型 |
| 同一种发票每次都错同一字段 | 版式固定、字段位置特殊 | 模板 / few-shot |
| 大部分发票都差 | 模型太小（3B）或图片太大被压缩 | 换 7B、调 `num_ctx`、控制图片尺寸 |
| 切图后变差 | 裁剪把字段切掉 | 已在 v0.3 改为整图识别 |

---

## 2. 最便宜有效：整图 + 少样本（推荐先做）

同版式发票（例如某连锁店的固定小票）不需要训练，只要给模型 1–3 个**示例图片 + 期望 JSON**，识别率会明显提升。

### 做法

1. 挑 5–10 张同版式、识别正确的发票；
2. 每张准备一份人工核对过的 JSON（字段与数据库一致）；
3. 放在：

   ```
   data/templates/<模板名>/
   ├─ sample1.jpg
   ├─ sample1.json
   ├─ sample2.jpg
   └─ sample2.json
   ```

4. 识别时先做一次轻量匹配（pHASH / ORB 特征 / 或首轮识别出的商家名），命中模板后，把示例图片和 JSON 一起放进提示词；
5. 提示词增加一句：“参考示例的字段位置和格式，但只输出当前图片的内容”。

> 当前版本还没有内置模板匹配，但 `tools/export_training_data.py` 已经把图片和字段成对导出，可直接用来整理模板样本。

### 什么时候有效

- 同一家店/同一种报销单反复出现；
- 字段位置固定，但模型总是把“合计”读成“小计”；
- 日期格式固定（例如 `R7.11.18`）。

### 代价

- 每次请求多一张示例图，延迟和显存上升；
- 模板太多会互相干扰，建议按商家分组、每次只带 1–2 张。

---

## 3. 固定版式：模板对齐 + 局部裁剪

如果某类发票的布局完全固定（例如公司内部的报销单），比起“让模型看整张图”，更稳的是：

1. 用模板图做 ORB/SIFT 特征匹配，估计单应矩阵，把当前图片**对齐**到模板坐标；
2. 按模板定义的区域裁出日期、金额、发票号；
3. 只把这些小图交给模型/OCR。

优点：

- 每个区域只包含目标字段，干扰少；
- 日期/金额可以用正则二次校验；
- 对 3B 小模型特别有效。

缺点：

- 每换一种版式就要做一次模板；
- 拍摄角度/透视太差时对齐会失败，需要回退到整图识别。

适合“几种固定发票占 90% 量”的场景，不适合杂乱的便利店小票。

---

## 4. 什么时候才做微调（LoRA）

### 数据量

- 每种版式至少 50–100 张，总体 200–500 张较稳；
- 必须有**人工核对过**的字段，`needs_review=1` 的样本先修正；
- 留 20% 做评测，不能全部训练。

### 模型与工具

- 基座：`Qwen2.5-VL-3B-Instruct` 或 `7B-Instruct`（Ollama 里的 `qwen2.5vl:3b/7b` 同源）；
- 工具：`ms-swift` 或 `LLaMA-Factory` 的 VLM LoRA；
- 硬件：7B 建议 24GB 显存起（QLoRA 可更低），3B 约 12–16GB；
- 训练后合并权重 → 转 GGUF → `ollama create` 导入。

### 数据格式

`tools/export_training_data.py` 导出的 `dataset.jsonl`：

```json
{"images":["images/000001.jpg"],
 "messages":[{"role":"user","content":"Read this receipt ..."},
             {"role":"assistant","content":"{\"invoice_no\":\"...\", ...}"}],
 "fields":{...}}
```

改造成 ms-swift 的 `{"query": ..., "response": ..., "images": [...]}` 即可。

### 风险

- 过拟合到某几家店，换版式反而变差；
- 小样本微调容易“背答案”，字段幻觉更严重；
- 训练/部署链路变长，升级模型成本高。

**建议**：先做少样本/模板；只有“同版式量大 + 人工标注充足 + 7B 仍不达标”时才微调。

---

## 5. 评测怎么做

准备 50 张**不参与训练**的真实发票，逐字段统计：

| 指标 | 说明 |
|---|---|
| 日期准确率 | 完全一致（含年份） |
| 金额准确率 | 分/日元完全一致 |
| 商家准确率 | 允许轻微空白差异 |
| 发票号准确率 | 完全一致 |
| 整单全对率 | 所有关键字段都对 |

只看“识别出文字”没有意义，必须看**入库字段是否正确**。

---

## 6. 推荐路线

1. 先换 `qwen2.5vl:7b`（如果显存允许），调大 `WECOM_OLLAMA_NUM_CTX`；
2. 收集 20 张真实发票，人工核对入库字段；
3. 用 `tools/export_training_data.py` 导出，挑 5–10 张做 few-shot；
4. 若某几种版式仍稳定出错，做模板对齐 + 局部裁剪；
5. 数据达到 200+ 且 7B 仍不达标，再考虑 LoRA。

---

## 7. 隐私提醒

发票图片包含商家、金额、地址，甚至客户姓名。用于训练/少样本前：

- 先脱敏（涂掉姓名、电话、地址）；
- 不要上传到公开仓库或第三方平台；
- 训练数据与生产数据分开存放，设置访问权限和保留期限。
