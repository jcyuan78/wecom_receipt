# 企业微信后台配置指南

> 目标：让别人发到企业微信里的图片/文件，自动进入本服务并落盘、触发处理程序。
>
> 本文先给结论：**企业微信没有开放"读取成员个人聊天"的接口**。别人直接发到你的个人企业微信会话，官方只有「会话内容存档」能拿到，且需要企业认证 + 按人付费 + 部署官方 SDK。
>
> 本仓库实现的是**自建应用**方案：别人把文件发给「文件助手」这个应用，应用就能实时收到。免费、稳定、不封号，适合先把整条链路跑通。

---

## 0. 三条官方路线怎么选

| | 自建应用（本文主推） | 会话内容存档 | 微信客服 |
|---|---|---|---|
| 能收到 | 成员发给**应用会话**的图片/文件/语音/视频 | 成员与同事、外部客户的**真实个人会话** | **外部微信用户**发给客服账号的图片/文件 |
| 典型场景 | 同事/助理/客户把资料发给「文件助手」 | 合规审计、销售会话管理 | 对外客服、售后收图 |
| 费用 | 免费 | 企业认证 + 按人购买许可 | 企业认证，额度以后台为准 |
| 开发量 | 小（本仓库已完成） | 大（官方 C SDK + RSA/AES + seq 拉取） | 中（事件回调 + sync_msg 拉取） |
| 合规要求 | 低 | 高（必须告知/同意） | 中（客服场景告知） |

**建议路径**：先用自建应用把"收文件 → 下载 → 触发"跑通（今天就能用），确认后半段分析流程后，再评估是否上会话存档。

---

## 1. 方案 A：自建应用（15 分钟，本仓库已支持）

### 1.1 前置条件

- 企业微信**管理员**或**应用管理员**权限（没有权限看 1.10）
- 企业微信客户端 4.x（手机/PC 均可）
- 一个公网可达的 **80/443** 地址（本机开发用 cloudflared 临时隧道即可）
- 本服务已能本地启动（`.\run.ps1`）

> 建议企业完成认证。未认证企业也能建自建应用，但部分能力（可信 IP、接口额度）会受限。

### 1.2 第一步：拿到企业 ID（CorpID）

1. 浏览器打开 <https://work.weixin.qq.com/>，用管理员企业微信扫码登录。
2. 进入**管理后台**。
3. 左侧「**我的企业**」→「**企业信息**」。
4. 页面底部「企业ID」形如 `ww1234567890abcdef`。

填入 `.env`：`WECOM_CORP_ID=ww...`

### 1.3 第二步：创建自建应用，拿 AgentId + Secret

1. 顶部「**应用管理**」→ 左侧「**应用**」→「**自建**」→ 点「**创建应用**」。
2. 上传 logo，应用名称填「**文件助手**」（名字随意，后面要发给它）。
3. 「可见范围」先只选**你自己**（调试期越小越好，后面再加人）。
4. 点「创建应用」，进入应用详情页。
5. 记录两个值：
   - **AgentId**：一串数字，如 `1000002`
   - **Secret**：点「查看」，企业微信会把 Secret 发到你的客户端；复制保存

填入 `.env`：

```ini
WECOM_AGENT_ID=1000002
WECOM_APP_SECRET=你的Secret
```

> Secret 等同于应用密码，不要发到群里、不要提交到 Git。

### 1.4 第三步：生成 Token 和 EncodingAESKey

在项目目录执行：

```powershell
.\.venv\Scripts\python.exe tools\gen_keys.py
```

输出两个值：

- **Token**：3–32 位字母数字（用于计算签名）
- **EncodingAESKey**：43 位字符（用于 AES 加解密）

也可以在企业微信后台点「随机获取」，但**生成后必须同时写进后台和 `.env`**，两边完全一致。

```ini
WECOM_CALLBACK_TOKEN=...
WECOM_CALLBACK_AES_KEY=...
```

### 1.5 第四步：先把服务跑起来，再暴露到公网（顺序很重要）

> ⚠️ 后台点「保存」时，企业微信会**立刻**向你的 URL 发一个 GET 校验请求。服务没启动、隧道没通，保存一定失败。

**① 启动服务**

```powershell
cd C:\path\to\wecom_receiver
.\run.ps1
```

看到 `服务已启动 corp=... processor=...` 即可。默认监听 `0.0.0.0:8080`。

**② 开一条公网隧道（开发期）**

```powershell
winget install --id Cloudflare.cloudflared
cloudflared tunnel --url http://127.0.0.1:8080
```

输出类似：

```
Your quick Tunnel has been created! Visit it at:
https://random-words-1234.trycloudflare.com
```

**③ 自检**

```powershell
curl https://random-words-1234.trycloudflare.com/healthz
# {"status":"ok","corp_id":"ww12***ef","worker_alive":true,...}
```

注意事项：

- 企业微信回调 URL **只支持 80/443**，所以 URL 里不要带 `:8080`。隧道给你的是 443，正合适（最终以保存时的提示为准）。
- 免费临时隧道**每次重启域名都会变**；变了要回后台改 URL，并保持 `.env` 不变（Token/AESKey 不变即可）。
- 正式环境建议：云服务器 + 域名 + Caddy/Nginx 自动 HTTPS；或 frp 把公网 443 映射到内网机器。不要把 8080 直接暴露到公网。

### 1.6 第五步：配置「接收消息」（核心）

1. 回到应用详情页，找到「**接收消息**」区块。
2. 点「**设置API接收**」。
3. 三个输入框：

   | 字段 | 填什么 |
   |---|---|
   | **URL** | `https://你的域名/wecom/callback` |
   | **Token** | 1.4 生成的 Token |
   | **EncodingAESKey** | 1.4 生成的 43 位 Key |

4. 点「**保存**」。

此时企业微信会向 `URL?msg_signature=...&timestamp=...&nonce=...&echostr=...` 发 GET 请求。本服务会验签、解密 `echostr` 并原样返回明文。看到「**已启用**」即成功。

失败的典型原因：

| 提示/日志 | 原因 |
|---|---|
| 后台提示"回调地址校验失败" | 服务未启动 / 隧道断开 / URL 路径写错 / 用了 8080 端口 / Token 或 AESKey 不一致 |
| 本服务日志 `403 签名校验失败` | `.env` 与后台的 Token/AESKey 不一致，或改完没有重启 |
| 本服务日志 `receive_id 不匹配` | `.env` 的 `WECOM_CORP_ID` 填错（不是应用 ID） |
| 502/504 | 隧道后面没有服务，或防火墙拦截 |

> 修改 URL / Token / AESKey 后，后台会重新校验；`.env` 同步修改并**重启服务**。

### 1.7 第六步：配置「企业可信IP」

先纠正一个最常见的误解：

| 方向 | 谁发起 | 是否受可信IP 影响 |
|---|---|---|
| **入站**：企业微信回调你的 URL | 企业微信 → Cloudflare → 你的服务器 | ❌ 不受影响 |
| **出站**：你的服务调用 `gettoken` / `media/get` | 你的服务器 → `qyapi.weixin.qq.com` | ✅ 只校验这里 |

所以：**可信IP 填的是你的服务器访问企业微信时的“出口公网 IP”，与 Cloudflare 的入站代理/隧道完全无关。**
Cloudflare 只改变“别人怎么访问你”，不改变“你怎么访问企业微信”。

#### 为什么不能填 Cloudflare 的 IP

- 请求不从 Cloudflare 发出，填了也不会生效。
- 企业微信会识别“第三方厂商 IP”并直接拒绝（提示：*The following IPs belong to a third-party vendor*）。
- 官方限制：**不支持网段/CIDR、不支持通配符、仅 IPv4、每个应用最多 120 个、英文分号分隔**。

#### 正确的查法

在**运行本服务的同一台机器、同一个网络环境**里执行：

```powershell
# 项目自带脚本：打印代理变量、多个站点看到的出口 IP，并试调 gettoken
.\.venv\Scripts\python.exe tools\check_egress.py
```

或手动：

```powershell
curl.exe -4 https://myip.ipip.net
curl.exe -4 https://ifconfig.me/ip
```

注意：

- 国内站点（`myip.ipip.net`）和企业微信的观测点更接近；不同站点结果不一致时，**以 60020 报错里企业微信给出的 IP 为准**（本服务日志现在会直接打印这个 IP）。
- **可信IP 只支持 IPv4**：如果机器同时有 IPv6，脚本会把两者分开显示，只有 IPv4 那一行能填。
- 如果设置了 `HTTPS_PROXY` / `ALL_PROXY`，或装了 Cloudflare WARP，查到的可能是代理出口，要先 `echo $env:HTTPS_PROXY` 确认。
- 容器里跑服务时，要在容器内查；容器 NAT 后的出口可能和宿主机不同。
- 云服务器：直接用控制台的弹性公网 IP。

#### Cloudflare 场景怎么配

| 你的拓扑 | 出站 IP | 可信IP 填什么 |
|---|---|---|
| Cloudflare 代理（橙云）→ 云服务器 | 云服务器 EIP，固定 | 云服务器 EIP |
| cloudflared 隧道 → 家里/公司内网机器 | 该网络宽带的公网出口 | 宽带公网 IP（不固定就要看下一节） |
| Cloudflare 代理 → 内网穿透（frp）→ 本地 | 本地宽带出口 | 本地宽带公网 IP |

#### 出口 IP 不固定（家宽 / CGNAT / 动态 IP）怎么办

企业微信**没有**提供修改可信IP 的开放接口，IP 变了只能后台手动改。三个可落地的方案：

1. **把服务迁到有固定 EIP 的云服务器**（最省心，推荐）。
2. **云服务器做出口代理**：让本机服务通过一台固定 IP 的云主机访问企业微信，可信IP 填云主机 EIP。
   - 云主机装 tinyproxy/Squid，只监听内网/本机；
   - 本机设置 `HTTPS_PROXY=http://云主机内网IP:8888`；
   - 本服务用的 httpx 默认 `trust_env=True`，会读取该环境变量。
3. **Cloudflare WARP / Gateway 出口**：不推荐。出口 IP 不固定、不公布，还容易被判为第三方 IP。

#### 填法与验证

1. 应用详情页 →「**企业可信IP**」→「配置」/「修改」。
2. 一行一个 IPv4（后台也接受英文分号分隔），保存。
3. 在服务器上跑一次 `tools\check_egress.py`，看到 `成功。access_token 前缀: ...` 即通过。
4. 仍然 60020：把日志里 `from ip: x.x.x.x` 的地址原样填进去；改完等 1–2 分钟再试。

> 2022-06-20 之后新建的自建应用强制要求配置可信IP；老应用可能不配也能用。一旦出现 60020，就是这里的问题。

#### 另一个方向：入站要不要放行 Cloudflare？

如果源站防火墙/WAF 做了 IP 白名单，需要放行 [Cloudflare 官方 IP 段](https://www.cloudflare.com/ips/)，并用 `CF-Connecting-IP` 头取真实来源。
但本服务的**安全边界是回调签名校验**（已实现），不依赖来源 IP；Cloudflare 只是传输通道。

### 1.8 第七步：填写 `.env` 并重启

字段对照表：

| 企业微信后台 | `.env` |
|---|---|
| 我的企业 → 企业信息 → 企业ID | `WECOM_CORP_ID` |
| 应用详情 → AgentId | `WECOM_AGENT_ID` |
| 应用详情 → Secret | `WECOM_APP_SECRET` |
| 接收消息 → Token | `WECOM_CALLBACK_TOKEN` |
| 接收消息 → EncodingAESKey | `WECOM_CALLBACK_AES_KEY` |

```powershell
copy .env.example .env
notepad .env
.\run.ps1
```

### 1.9 第八步：验收

1. 浏览器访问 `https://你的域名/healthz`，返回 `{"status":"ok",...}`。
2. 手机企业微信 →「**工作台**」→ 打开「**文件助手**」→ 在应用会话里发一张图片。
   - 部分客户端入口在应用页右上角「…」→「发消息」。
   - 如果找不到会话入口：确认「可见范围」包含你；退出企业微信重新登录；或先通过 `message/send` 接口给成员发一条应用消息，会话会出现在消息列表。
3. 观察服务日志：

   ```
   收到消息 type=image from=zhangsan msg_id=xxxx media_id=yyyy
   下载媒体 msg=xxxx ...
   已保存文件 ...\data\inbox\2026-11-15\xxxx\screenshot.png
   消息 xxxx 处理完成（screenshot.png）
   ```

4. 手机应收到自动回复「文件已收到，正在处理中。」（可用 `WECOM_AUTO_REPLY` 改，留空关闭）。
5. 检查 `data/inbox/<日期>/<MsgId>/` 和 `data/jobs/<MsgId>.json`。

### 1.10 没有管理员权限怎么办

- 让企业管理员按本文操作，或请管理员给你「应用管理员」权限（应用管理 → 权限管理）。
- **自己注册一个企业微信企业**（免费，个人可注册）当测试环境，你是管理员；跑通后再迁到公司。
- 不建议用个人微信 hook：违反协议、随时封号、接口不稳定。

### 1.11 让"别人"能发给你

- **同事/团队成员**：把「文件助手」加入可见范围，他们在工作台打开应用即可发。
- **外部客户/朋友（微信）**：不能直接发给自建应用。两条路：
  1. 让他们发给你，你再转发给「文件助手」；
  2. 用**微信客服**（见方案 C），外部微信用户可以直接给客服账号发图片/文件。
- 如果是固定协作方，可以给对方一个说明：「请在企业微信里搜索/打开 XX 企业的文件助手」。

### 1.12 边界：自建应用收不到外部微信用户的消息

这一点决定了方案选型，单独说明：

| 场景 | 自建应用 | 说明 |
|---|---|---|
| 本企业成员发给应用（单聊） | ✅ 支持 | 图片/文件/语音/视频均可 |
| 本企业成员在**内部群**里 @应用 | ⚠️ 有限 | 应用消息可发内部群，但群内消息回调能力有限；图片/文件建议走单聊 |
| 外部联系人 / 微信用户发给应用 | ❌ 不支持 | 外部用户看不到、也加不了自建应用 |
| 把应用加进**外部群/客户群** | ❌ 不支持 | 官方明确：外部群不支持添加自建应用或智能机器人 |
| 群机器人 webhook 收消息 | ❌ 不支持 | 群机器人只能"发"，不能"收" |
| 客户群消息"发出去" | ✅ 有限 | 只能用「创建企业群发」，且需成员手动确认，不是 API 直发 |
| 读取成员与外部客户的真实会话 | ❌ | 只能走**会话内容存档** |

补充：企业微信还有另一种应用类型「**智能机器人**」，单聊里可以收图片、文件、视频（文件/视频 ≤100MB），群聊里被 @ 时支持文本和图文混排；但它同样不能加入外部群，也不能替代会话存档。

所以：

- 只服务**内部同事/助理** → 自建应用足够，本仓库直接可用。
- 要收**外部微信用户**发来的图片/文件 → 用**微信客服**（方案 C）。
- 要覆盖**个人会话/客户会话**的全部内容 → 只能**会话内容存档**（方案 B）。

## 2. 方案 B：会话内容存档（要抓"别人直接发我"的真实会话）

### 2.1 它能做什么

开通后，企业微信会把**指定成员**的会话内容（含与外部微信客户的聊天）加密推送到企业自己的服务器。你可以在自己的服务器上解密、入库、提取图片/文件。

这是唯一能官方覆盖"别人直接发到我的企业微信个人会话"的方案。

### 2.2 门槛（先确认再投入）

1. **企业已认证**（验证主体）。
2. **购买会话内容存档许可**：按成员/年计费，通过企业微信官方或服务商购买。
3. 管理后台**开通并设置存档范围**（哪些成员、是否含外部会话）。
4. 服务器部署**官方 SDK**（Linux/Windows 的动态库），自己实现拉取、解密、媒体下载、seq 持久化。
5. **合规**：必须告知员工并取得同意；涉及外部客户的，要符合《个人信息保护法》《数据安全法》及当地要求，只采集业务必要范围。

### 2.3 后台配置步骤

> 菜单名会随版本变化，以下为常见路径。

1. 完成企业认证：管理后台 →「我的企业」→「企业信息」→ 认证。
2. 开通服务：管理后台 →「**安全与管理**」→「**会话内容存档**」（部分版本在「管理工具」下）。
3. 选择开启范围（成员），购买/分配许可。
4. 生成 **RSA 密钥对（2048 位）**：
   - 公钥上传到企业微信后台（「会话内容存档密钥」）；
   - **私钥留在自己服务器**，用于解密每条消息的 `encrypt_random_key`。
5. 记录页面上的 **Secret**（会话存档专用 Secret，不是自建应用 Secret）和 **CorpID**。
6. 配置**可信 IP**（调用 `gettoken` 的出口 IP）。
7. 在该页面下载 **会话内容存档 SDK**（含各语言示例）。

### 2.4 技术流程（自研时）

```
gettoken(会话存档 Secret)
   ↓
SDK.GetChatData(seq, limit, proxy, passwd, timeout)
   ↓ 每条：encrypt_random_key + encrypt_chat_msg
RSA 私钥解密 encrypt_random_key → 32 字节 AES key
   ↓
AES-256-CBC(PKCS7) 解密 encrypt_chat_msg → JSON
   ↓
message.msgtype = image / file ... → SDK.GetMediaData(sdkfileid) 分片拉取
   ↓
落盘 + 写入本仓库的 messages 表 → 复用下载后的 job 契约
```

要点：

- `seq` 必须自己持久化，单调递增，重启后从上次位置继续。
- 没有实时推送，通常 10–60 秒轮询一次。
- 媒体文件要用 `sdkfileid` 分片拉取（`is_finish` 判断结束），不能直接用普通 `media/get`。
- 语音等特殊消息需要额外转码/分片处理，建议先只做图片和文件。

### 2.5 为什么本仓库还没内置

- SDK 是二进制动态库，需要企业许可才能下载，无法随仓库分发。
- 消息体格式、鉴权、媒体拉取都与自建应用不同。
- 架构上已经预留：新增一个 `archive` 采集器，把解析后的消息写入同一张 `messages` 表，后面的下载/job/处理完全复用。

### 2.6 合规红线

- 未告知员工就开启存档，风险极高。
- 不要采集与业务无关的私人聊天。
- 图片/文件可能含个人信息，建议设置保留期限、访问审计、加密存储。

## 3. 方案 C：微信客服（外部微信用户直接发文件）

适合"客户在微信里发图片/文件给你"的对外场景。

### 3.1 门槛

- 企业已认证。
- 管理后台开通「微信客服」，创建客服账号。

### 3.2 后台步骤

1. 管理后台 →「**应用管理**」→「**微信客服**」→ 开通。
2. 「客服账号」里创建一个账号（如「资料接收」），得到客服账号 ID。
3. 打开「**开发配置 / API**」页面：
   - 记录 **Secret**
   - 配置**回调 URL**、**Token**、**EncodingAESKey**（与自建应用同样的校验方式）
   - 配置**可信 IP**
4. 把客服二维码/链接发给外部用户，对方用微信扫码即可发图片、文件。

### 3.3 技术流程

```
用户发消息 → 企业微信回调事件 kf_msg_or_event（只给 Token，不给消息体）
   ↓
调用 cgi-bin/kf/sync_msg(cursor, token, limit) 拉取
   ↓
msgtype = image / file → 有 media_id
   ↓
cgi-bin/media/get 下载（与自建应用相同）
```

注意：客服消息是**拉取式**，要维护 `cursor`；普通文本/图片在客户端有会话窗口限制，以官方文档为准。

## 4. 个人微信：为什么不做

- 微信个人号**没有**开放消息 API。
- 网上常见的 itchat / Wechaty puppet / PC 协议 hook，本质是逆向或模拟登录，违反《微信软件许可及服务协议》，**有封号风险**，且经常随版本失效。
- 如果目标是"接收别人发来的资料"：用企业微信自建应用（内部协作）或微信客服（外部客户）替代，稳定且可长期维护。

## 5. 排错手册

### 5.1 回调保存失败

| 检查项 | 做法 |
|---|---|
| 服务是否在跑 | `curl http://127.0.0.1:8080/healthz` |
| 公网是否可达 | `curl https://你的域名/healthz`（从外网/手机流量试） |
| 路径是否精确 | 必须是 `/wecom/callback`，区分大小写，末尾不要多 `/` |
| 端口 | 只支持 80/443；不要把 `:8080` 写进后台 |
| Token/AESKey | 与 `.env` 逐字符比对；改完重启 |
| CorpID | 必须是"企业ID"，不是 AgentId |
| 证书 | HTTPS 证书必须有效（临时隧道自带有效证书） |

开启 DEBUG 日志看详细原因：

```ini
WECOM_LOG_LEVEL=DEBUG
```

### 5.2 能保存，但收不到消息

1. 应用「可见范围」是否包含发送人。
2. 「接收消息」是否显示已启用。
3. 发送人是否真的发到了**这个应用**的会话（不是发给某位同事）。
4. `tail data/logs/receiver.log` 有没有 `收到消息`。
5. 如果日志完全没有请求：URL 配到了别的环境/隧道域名变了。

### 5.3 报错 60020

`not allow to access from your ip` → 1.7 的「企业可信IP」没配或 IP 变了。

### 5.4 下载失败

- `media_id` 有效期 **3 天**，过期无法补拉；本服务收到即下载。
- 应用需有接收消息/媒体权限（默认有）。
- 检查服务器出网是否正常（能访问 `qyapi.weixin.qq.com`）。

### 5.5 重复收到同一条消息

企业微信 5 秒内没收到响应会重试（最多 3 次）。本服务按 `MsgId` 去重，不会重复落盘。若你看到多条日志，确认 `MsgId` 是否相同。

### 5.6 中文文件名乱码

企业微信通过 `Content-Disposition` 返回文件名，可能是 `filename*=UTF-8''...` 或百分号编码。本服务已兼容；若仍乱码，把响应头原文发我。
